# Code review: astro @ 6d4fdf2 (2026-10-04)

The only source of requirements for this review is `docs/requirements.md`; IDs like **S3** and
**G2** refer to it. It covers every tracked file under `astro/`, `web/`, `firmware/`,
`scripts/`, `deploy/`, `config/`, plus CI, docs and the tests at a high level.

Baseline: `ASTRO_SIM=1 pytest -q` → 247 passed. `ruff check .` → clean.

## How to use this file (for the agent picking it up)

- Findings are ranked by severity. **H** = safety or user-facing correctness, fix first.
  **M** = a requirement gap or robustness issue. **L** = a nit, cleanup or doc drift.
- Each finding gives: location, the requirement it touches, what is wrong, a repro or evidence
  where I had one, and a suggested fix. "Verified" means I ran it. The rest comes from reading
  the code.
- Per CLAUDE.md: use small PRs, one topic each, with Copilot review. Add a regression test for
  every H item. Don't bundle the nits with behavior changes.
- Some items are requirement gaps where the requirement may be the thing to change, for example
  V5 tool names or CV7 SQLite. Those are marked **(decide)**: ask the developer before building
  anything.

## H: fix first

### H1. Guide says "keep going" when it means "stop" (verified)
- `astro/guidance/engine.py:78`, touches **G2**.
- `spoken = "keep going" if text == self._last_text else text` swaps in "keep going" for *any*
  repeated text, "stop" and "slower" included. Here is the failure: one axis lines up
  (axis-level "stop"), the next cue gets rate-limited, and the user arrives on target. The
  on-target "stop" is urgent, but `_last_text == "stop"`, so the user hears **"keep going"
  while on target**.
- Repro (verified):
  ```python
  g = Guide(45.0, 100.0, tolerance_arcmin=4)
  for alt, az, t in [(44.0,100.14,0),(44.99,100.14,2.0),(44.99,100.14,2.1),(44.99,100.07,2.5)]:
      print(g.update(alt, az, t)[1])
  # t=2.5: on_target=True, cue text 'keep going'
  ```
- Fix: only substitute "keep going" for directional cues (`push …`, `… getting closer`,
  `… a little`). Never substitute for "stop", "slower" or "passed it…". Add the repro as a test.
- Related: a non-urgent repeated "stop" (axis lined up a second time within 4 s) is suppressed
  completely, so the user is not told to stop. Make the axis "stop" urgent whenever the user was
  last told to move.

### H2. Finder exposures before the first sync aren't safety-checked
- `astro/pointing/finder_sync.py:132-135` (`FinderSync.sync` captures with no check). Callers:
  `session.py:247` (goto), `:298` (where), `:454` (start_horizon), `:490` (wizard sync), and
  `solve_tracker.py:81-88`, which captures continuously around the clock. Touches **S2**,
  **S3**, **H4**.
- S3 says that before the first sync, exposures are allowed only with the Sun down. Today a
  daytime "go to Saturn" goes straight to `finder.sync()`, which exposes the finder. The goto
  is refused only afterwards, by `check_target`. With `mount.driver = "solve"`, the
  `SolveTracker` thread exposes and solves all day long.
- Fix: put one exposure gate in front of every finder capture. Either `FinderSync`/
  `SolveTracker` take a `safety: Callable[[], str | None]`, as `Recorder` does, or the session
  calls `exposure_safety()` before each `finder.sync()`. The tracker loop should idle while the
  gate says no. Add tests that a daytime goto/where/setup never calls `camera.capture()`.

### H3. goto ignores the horizon mask
- `astro/session.py:252` → `astro/safety.py:37` checks only `alt < 0`. Touches **S4**.
- The planner respects the mask (`tonight.py:78`), but "go to M13" behind the trees starts
  guidance anyway. The S1 re-check in `_tick` (`session.py:343`) has the same gap.
- Fix: pass the mask into the safety check, or add a second check in `goto` and in `_tick`.
  Give a spoken reason such as "it's behind the trees right now". Add a test using a mask at
  60°.

### H4. "Stop / finish the horizon walk" restarts the walk and drops every mark (verified)
- `astro/intents.py:22`. The pattern `\bhorizon walk\b` matches anything that mentions the
  walk. Touches **V6**, **PL4**.
- `parse("stop the horizon walk")`, `parse("finish the horizon walk")` and
  `parse("I'm done with the horizon walk")` all return `horizon_start`. `start_horizon()` then
  sets `self._horizon = []`, which loses every mark.
- Other misparses I verified:
  - `"calibrate the horizon"` → `setup`, because `calibrate` is in the setup pattern.
  - `"finder focus"` → main-camera `focus`.
  - `"show me Saturn tonight"` and `"take me to the Moon tonight"` → `tonight`, not goto.
  - `"next step"` outside the wizard → `skip` → nulled → "Sorry, I didn't catch that."
  - `match_name("messier 57")` → None. Whisper often writes "Messier 57" or "M-57" (the latter
    works).
- Fix:
  - Anchor `horizon_start` to start verbs only.
  - Check stop/finish/done-with *before* start patterns.
  - Make `finder focus` and `focus finder` both map to finder focus.
  - Let goto beat `tonight` when a target name is present.
  - Normalize `messier` to `m`.
  - Add these phrases to `tests/test_intents.py`.

### H5. Guidance keeps talking during a deep-sky live stack
- `astro/session.py:217-239` (`capture()` clears `_centering` but not `self.guide`), together
  with `_tick` at `:338-354`. Touches **G2**, **C4**.
- For non-planet targets `_should_center()` is False, so the guide stays active after "stop".
  The scope doesn't track, so within about 25 s the target drifts past 1.5× tolerance, and the
  guide starts saying "right a little" in the middle of a 90 s stack that told the user "Try not
  to touch the telescope." The same thing happens if the user says goto while recording:
  `goto` doesn't check `_camera_busy()`.
- Fix: suspend the guide while `_camera_busy()`, and decide what happens after the picture
  (resume or stay quiet). Make `goto` refuse, or stop the capture first, while the camera is
  busy. Add a test.

### H6. Centering repeats a cue every 0.5 s and talks over itself
- `astro/guidance/centering.py:65-68` returns a cue on every `update()`. `session.py:366-384`
  calls it every `CENTER_STEP_S = 0.5`. In `web/index.html:51-53`, each new audio stops the
  previous one. Touches **G2**, **V4**.
- Result: "push ri— push ri— push right a little…" for the whole centering pass. None of these
  phrases are in `cue_phrases()`, so they aren't pre-rendered either.
- Fix: rate-limit and dedupe centering cues the way `Guide` does (min interval, repeat
  interval, "keep going"). Add the centering phrases to `cue_phrases()` (or a sibling list) so
  `Tts.warm` caches them.
- Related, in `session.py:382`: control flow depends on
  `step.say.startswith("I can't see it")`. Add a `lost: bool` to `Step`. Also, "Let's go back
  to the last spot" promises an action nobody takes: centering just stops and guidance is
  `None`. Either restart the guide to the target or change the wording.

### H7. Setup wizard races the GPS fix
- `astro/wizard.py:29-33` and `astro/session.py:525-545`. Touches **V7**, **V9**.
- `start()` asks for the location and prompts for the first sync right away. The fix arrives
  asynchronously, after up to 20 s (`index.html:92`). If the user says "ready" first and the
  fix is more than 1 km from `config/site.toml` (likely on a fresh install), `set_location`
  calls `finder.reset()`. That wipes the sync just made, while `wizard.syncs_done` still says 1.
- Fix: have the wizard wait in a `location` step until `set_location` (or `location_error`)
  arrives. Alternatively, reset `syncs_done` when the finder is reset.

### H8. Moving more than 1 km keeps the old site's treeline
- `astro/session.py:537-541` resets the mount model and target but not `self.horizon`.
  Touches **S4**, **PL1**, **V7**.
- At the new place, the planner hides targets behind trees that aren't there, and once H3 is
  fixed, goto will refuse them too.
- Fix: on a move, reset to the default mask and call `on_horizon_change`, or key saved masks by
  site. Also clear `_horizon` (a walk in progress), `_suggestions`, `_focus_coach` and
  `_centering`.

### H9. Planner times are spoken in UTC, and "tonight" asked in the afternoon finds nothing (verified)
- `astro/session.py:271,290` and `astro/planner/tonight.py:91,97-101`. Touches **PL1**, **M2**.
- `Choice.best_time` takes `start.tzinfo`, and the session clock is UTC. The agent therefore
  reads "Saturn (best around 05:15)", which is 1:15 AM EDT.
- `plan()` starts from *now*. Asked at 4 PM local, "what's good tonight" answers "Nothing good
  is up right now." (verified). `start_of_evening()` exists and is tested but never used. It
  also compares `now.hour` on a UTC datetime, so it's wrong as written.
- Fix: carry a local timezone, derived from the site (for example via `timezonefinder`, which
  is OSS) or from the tablet (send `Intl.DateTimeFormat().resolvedOptions().timeZone` with the
  location). Format times in local time and plan from dusk when asked during the day. Replace
  `start_of_evening`'s hour test with "Sun below −12° within the next N hours".

### H10. Offline with an API key, "what's good tonight" waits up to ~30 s
- `astro/agent.py:87-88` always sends `tonight` to Claude. `agent.py:138` sets `timeout=15.0,
  max_retries=1`. Touches **H5**, **V4**, **V6**.
- On the field hotspot (WiFi up, no internet), every "tonight" and every unparsed phrase blocks
  for the full timeout before falling back. Successful calls take two LLM round trips (tool
  call, then reply), which also misses "understood within about a second".
- Fix:
  - Answer `tonight` offline first (`session.tonight()` is already spoken-friendly).
  - Keep an "online" flag that flips off after one connection error and is re-probed in the
    background.
  - Use a short connect timeout (`httpx.Timeout(connect=2, read=10)`).
  - Say something ("Let me think…") if the LLM call goes past about 1 s.

### H11. Heaters, cameras and the solve thread aren't closed on shutdown
- `astro/server.py:78-96`. `build_real_session` gets `close_pointing` but drops it on success.
  Nothing closes the main camera, the MCU or the tracker on shutdown. Touches **S5**, **R3**.
- S5 says "off … on host shutdown". Today that relies only on the firmware's 10 s heartbeat.
- Rollback is also incomplete: if `Session(...)` itself raises (corrupt `data/horizon.toml`,
  bad `targets.toml`), both cameras stay open, and the next connection fails with "camera
  busy".
- Fix: add a shutdown handler (FastAPI lifespan) that calls `close_pointing()` and
  `main.close()`, which in turn sends `HEAT 0`. Wrap the whole build in one try/except that
  closes everything opened.

### H12. The cert timer restarts the server at midnight on the 1st
- `deploy/astro-cert.timer` (`OnCalendar=monthly` = 1st, 00:00) and `deploy/astro-cert.service`
  (`ExecStartPost=+/bin/systemctl restart astro`). Touches **R2**.
- The restart is unconditional and lands in the middle of an observing night. It drops
  guidance, the mount model, the camera axes and any recording in progress.
- Fix: run in the daytime (`OnCalendar=*-*-01 12:00`), and restart only if the cert file
  changed (compare mtime or hash in `tailscale-cert.sh`).

### Robustness
- **M1. Exceptions in the WebSocket handler drop the tablet** (`server.py:211-236`), touches
  **R2**. Any of these escapes the loop and closes the socket with nothing spoken:
  - `json.loads` on a bad frame
  - `KeyError`/`ValueError` on `data["lat"]`
  - `subprocess.CalledProcessError`/`TimeoutExpired` from `stt.transcribe`
  - any exception from `agent.handle` (session code isn't wrapped; only `anthropic.APIError` is)

  Wrap per message, log, and say "Sorry, something went wrong." `get_hub()` failing on real
  hardware should also be spoken before closing. Tick failures (`:175-177`) are logged but
  never spoken; speak once per failure streak.
- **M2. MCU unplug is silent and permanent** (`devices/mcu.py:81-91`), touches **R2**,
  **HW5**. After a `SerialException`, the reader sleeps and calls `readline()` on a dead handle
  forever. It never reopens, and the device may come back as `ttyACM1`. `counts()` keeps
  returning the frozen position, so guidance gives confident but wrong cues. Fix: reopen on
  error, track the last-POS time, and have the session say "I lost the encoders" and stop
  guiding when POS is older than about 1 s.
- **M3. No host-side ENV staleness check** (`mcu.py:63-71`), touches **S5**. Heater power
  changes only when an ENV arrives. If the BME280 starts sending `ERR` or nothing at all, the
  host keeps PINGing and the heaters stay at the last percentage indefinitely. Turn the heaters
  off when no valid ENV has arrived for about 5 s.
- **M4. A firmware watchdog reset zeroes the encoder counts silently** (`firmware/astro_mcu.ino:176-178`
  and `setup()`). Nothing tells the host, so the mount model goes wrong without anyone knowing.
  Send `VER` (or `BOOT`) from `setup()`. On an unexpected `VER`, the host should mark
  `finder.synced = False`.
- **M5. Weather fetch and planning run inside the session lock** (`session.py:260-267`,
  `:270-272`, `:515`, called from `handle()`/`status_text()`). Open-Meteo's 3 s timeout, and
  roughly 0.5 s of astropy per `plan()` on a laptop (more on the N150), block the 10 Hz
  guidance tick. Fetch weather off-lock in the background. Separately,
  `tonight_by_category()` (`:285`) is called from the agent thread **without** the lock,
  racing `_clouds`.
- **M6. TTS synthesis blocks the guidance loop** (`server.py:150-162`, `:178-181`).
  `broadcast` awaits `tts.synthesize` for uncached sentences, and the guidance loop awaits
  `broadcast`. A long agent reply can delay the next "stop". Separately, two concurrent
  `broadcast`s (agent reply and tick) can interleave `send_json` and `send_bytes`. Use a single
  per-hub send queue and synthesize off the loop.
- **M7. SolveTracker position goes stale with no signal** (`pointing/solve_tracker.py:48-50`),
  touches **HW9**. While the user pushes, solves fail from blur, and `position()` keeps
  returning the last fix. The guide keeps saying "push left" from old data and then reports
  "passed it" late. Expose the age of the fix, and have the session hold cues (or say "hold
  still for a second") when it's older than about 2 s.
- **M8. Mount model has no outlier rejection** (`pointing/mount_model.py:55-58`), touches
  **O4**. One false solve, or a bumped base, poisons every later fit until a site reset. After
  each fit, drop the sync with the biggest residual if it's much worse than the others, or cap
  the history at the last N syncs. While there: `fit_tilt = True` followed by `if fit_tilt:`
  (`:69-72`) is dead code. The RMS comment at `:83` ("2 independent components per sync")
  doesn't match the division by `len(self.syncs)`.
- **M9. Captures are never pruned.** `data/captures/*.ser` at 512² × ~100 fps × 60 s comes to
  about 1.5 GB per recording, so the MeLE disk will fill. Delete the SER after a successful
  `process_ser` (or keep the last N), and check free space before `Recorder.start`.
- **M10. The gallery can serve half-written files** (`capture/live_stacker.py:117`,
  `server.py:247`, `session.py:511`). The temp name is `*.tmp.png`, which matches `*.png`. Name
  it `*.png.tmp`. The live preview also lives in `gallery/` from the first frame, so an
  unfinished stack shows up as a picture. Write previews elsewhere and move them in when done.
- **M11. A recording that drifts out of view is never processed** (`session.py:317-319`). Any
  `rec.error` skips `process_ser`, even when 50+ good frames were saved ("planet drifted out
  of view"). Process whenever `frames >= MIN_FRAMES`.
- **M12. The main-focus gate can be passed without focusing** (`session.py:144-148`). Saying
  "done" right after "focus" sets `main_focus_ok = True` with zero measurements. Require at
  least a few scores, or a "passed it" peak, before accepting (**F2**).
- **M13. Tests write into the repo and read the real `.env`** (`server.py:40-49`, `:251`),
  touches **R5**. Importing `astro.server` runs `load_env()` and `GALLERY.mkdir()` at import
  time. `data/gallery/` gets created in the checkout by the test run. `tests/test_server.py:3-5`
  avoids the API key only because it sets the env vars before importing. Move these side
  effects into the lifespan/startup code. The sim `build_session()` also wires the real
  `cloud_cover_pct` (`server.py:74`), so any sim test that says "what's good tonight" would hit
  Open-Meteo. Inject the weather function, or no-op it when `ASTRO_SIM=1` plus a test flag is
  set.
- **M14. A failed API call can run tools twice** (`agent.py:79-82`). If an `APIError` hits
  after tool rounds have already run (for example, a goto started), the fallback runs
  `session.handle(text)` on the free-form text. That can do the action again or say "Sorry, I
  didn't catch that" after the action already happened. Return the side effects collected so
  far plus a short spoken apology instead.
- **M15. The agent routes through the text grammar** (`agent.py:118-132`, `_COMMANDS`). Tool
  calls go out as English and get re-parsed, for example `goto` → `f"go to {target}"`. A target
  like "the Moon tonight" or "Andromeda (M31)" then misparses (see H4). Call session methods
  directly (`session.goto(match_name(...))` under the lock).
- **M16. Camera reopen failure is permanent** (`devices/svbony.py:136-138`), touches **HW10**.
  If `connect()` fails during `_reopen` (USB re-enumeration), `_id` stays `None`, and every
  later `capture()` raises "camera not connected" with no retry. Retry `connect` with backoff
  inside `capture`.
- **M17. Possible HTTPS dependency on the internet** (**V2**/**H5**, to verify). The mic needs
  HTTPS, and HTTPS uses a Tailscale cert on a `*.ts.net` name. Check that the tablet can still
  resolve and reach that name on the field hotspot with no internet (MagicDNS and the
  coordination server). If it can't, voice input fails offline. A self-signed LAN cert is the
  fallback the requirement names, and it isn't implemented.
- **M18. No access control** (`server.py`). Anyone on the WiFi or tailnet can drive the session
  and read the gallery. That's low risk at home, but worth a shared token in the PWA URL before
  using public hotspots.

## L: nits, cleanup, doc drift

### Design and readability (D1)
- `session.py` is 569 lines, `Session.__init__` takes 13 parameters, and `_handle` is a
  19-branch if-chain. Use a dispatch dict `{intent_name: method}`, and group the capture
  objects into one small `Imaging` holder.
- `say()` is duplicated in `session.py:568` and `wizard.py:15`.
- `_extended_targets()` (`session.py:564`) rebuilds a constant set on every call. Make it a
  module constant.
- `TOLERANCE_ARCMIN = {False: 4.0, True: 2.0}` (`session.py:41`) is keyed by bool. Two named
  constants read better.
- The magic sensor size `(3856, 2180)` appears in `session.py:60` and `server.py:92`.
  `astro/optics.py` (**O1**) isn't used by any runtime code; the plate scales and drift appear
  only as comments next to magic numbers (`main_offset.py:19-21`, `live_stacker.py:20`,
  `session.py:43`). Either use it or say in a comment that it's reference math.
- `GOOD_ALIGNMENT_ARCMIN` (`wizard.py:10`) and `LOOSE_SYNC_ARCMIN` (`finder_sync.py:49`) are the
  same 10′ threshold. Keep one.
- `centering.py:83` reads `self.axes._sky`, a private attribute of another class. Add
  `CameraAxes.moves -> int`.
- `live_stacker.py:54`: `self._restore` is first assigned in `start()`, not `__init__`.
- `sim/main_cam.py:104` lazily creates `_tiles` via `self.__dict__.setdefault`. Initialize it
  in `__init__`.
- `finder_sync.py:40-41`: `MIN_STARS = 4` and `FEW_STARS = 3` are confusingly named;
  `FEW_STARS` really means "fewer than this is a star or two". `check_focus` also reuses `n`
  for two different counts (`:70` vs `:73`).
- The `or`-on-a-numpy-float trick at `finder_sync.py:68` is clever but obscure. Write it as an
  explicit `if mad == 0`.
- Extra blank lines inside classes and functions: `session.py:385-386`, `:402-403`;
  `speech.py:30-32`; `sim/main_cam.py:114-115`. Ruff runs with only `line-length` set. Consider
  `select = ["E", "F", "W", "I", "B", "UP"]`.
- FastAPI `@app.on_event("startup")` is deprecated. Use `lifespan`, which also fixes H11 and
  M13.
- `server.py:119`: `stt, tts = Stt(), Tts()` sits between two startup hooks. Move it next to
  the other module state. Same for `_real_hub`, which is declared after the function that uses
  it (`:197`).
- `server.py:65` reaches into `solver()._t3.star_table` (private). Add
  `FinderSolver.star_table`.

### Interfaces
- The `Camera` protocol (`devices/base.py:17-29`) lacks `exposure_s`, `gain` and `sensor_size`,
  which callers use (`live_stacker.py:54` via `getattr`, `server.py:92`). `SimCamera` names it
  `exposure` (`sim/camera.py:15`), so stack mode restore silently does nothing there.
  `SimMainCamera` and `SimFinderCamera` have none of these. Add them to the protocol and all
  three fakes.
- `config.py:73-74` repeats the `9216` default. Use `encoders.COUNTS_PER_REV`.
- `config.validate` raises `KeyError` on a missing section instead of a clear `ValueError`.
  It's also called twice (`server.py:83` and `config.py:55`).
- `config.py:68-72`: if `Mcu(...).start()` fails after the serial port opened, the port stays
  open.

### Pointing and solving
- `platesolve.py:26`: the comment `# horizontal, from astro.optics for 1280 px x 31"/px`
  belongs to `FINDER_FOV_DEG` (`:20`), not `_RING`.
- `platesolve.py:93-96`: `scale_arcsec_px` uses `image.shape[1]`. With `bayer=False` (as in
  `FinderSync.sync`), that's binned pixels (~62″), not sensor pixels (~31″) as the comment
  claims. Pass the binning factor explicitly.
- `finder_sync.py:143` and `solve_tracker.py:77`: `clock()` is read *after* a solve that can
  take up to 2 s. Capture the time with the frame.
- `sky_test.py:18-20`: `SOLVED = "solved"` vs `OUTCOMES` containing `"solves"`. `test_frame()`
  keys outcomes by *sentence* (`focus.reason`), while `classify()` uses codes. Also,
  `test_frame` starts with `test_`, so pytest would collect it if it were ever imported by name
  into a test module. Rename it to `check_frame`.
- `roi.py:24-25`: `roi_around` returns a negative x/y when `size > sensor`. Clamp with
  `max(0, …)` after the `min`.
- `roi.py:13`: the brightness floor `10` assumes 8-bit. Fine today; make it a named constant.
- `sim/main_cam.py:106`: the tile seed uses `i % 3600`, but RA tiles are 0-359, so tiles −1 and
  359 get different stars and the field jumps at RA 0h. Use `i % 360` (and wrap `ra - ra0` at
  `:87`).
- `main_offset.py:21`: `MIN_MOTION_DEG = 0.08` is fine, but the comment math (0.039°/count ≈
  280 px) belongs next to an `optics` call.

### Capture and processing
- `recorder.py:83` uses `checked = -SAFETY_CHECK_S`, while `live_stacker.py:75` uses `-1e9`.
  Pick one idiom.
- File names come from `name.replace(' ', '_')` (`recorder.py:72`, `live_stacker.py:63`).
  Sanitize to `[A-Za-z0-9_-]`, since a catalog name with `/` or `'` would break or look odd.
- `livestack.py:40` reuses the finder-tuned `check_focus` on main-camera superpixel luminance.
  `SATURATED_BINNED = 1000` never triggers on a 0-255 mean. Either parametrize it or note that
  it's only a star count here.
- `livestack.py:16`: `MIN_STARS = 6` may reject double-star targets (2 bright stars, few
  others at 0.2 s). Double stars are a **PL2** category. Consider the planetary path for them,
  or a lower bar.
- `LiveStack.status.frames_skipped` and `LiveSession.skipped` track the same thing.
- `ser.py:42-43`: SER `DateTime` (local) and `DateTime_UTC` both get UTC ticks. The `size =
  (height, width)` naming is easy to misread; call it `shape`.
- `focus.py:46-47`: an idle user hears "that's the sharpest so far" every second. Suppress
  repeats.

### Planner
- Moonlight uses separation only (`tonight.py:85-88`), not phase. A full Moon 40° away still
  ruins galaxies at Bortle 8. Scale by illumination.
- `config/targets.toml:18`: the Pleiades note says "wider than the eyepiece". The user views on
  the tablet (agent prompt), and the 2° cluster won't fit the 32′ main field anyway. Reword the
  note, or drop the Pleiades from capture suggestions.
- `weather.py:16`: `http.client.IncompleteRead` / `RemoteDisconnected` aren't `OSError`.
  Catch `Exception` there; it's a best-effort call. Round lat/lon to 2 decimals in the URL;
  that's plenty for a forecast and leaks less.
- `horizon.py`: interpolation across a large unmarked gap (say, marks only from 90-180°) draws
  a straight line across the gap. Warn when the marks cover less than about 270° of azimuth.

### Agent
- `agent.py:18-23`: the system prompt hard-codes "he/his". `docs/requirements.md` doesn't state
  the user's pronouns. Use neutral wording ("the user") unless the developer confirms.
- `Agent.history` is shared and mutated without a lock. Two tablets talking at once can
  interleave turns.
- `MAX_TOOL_ROUNDS` exhaustion (`agent.py:98-113`) speaks the text of a `tool_use` response,
  which is often empty, so the user hears "OK.". Do one final call with `tool_choice: none`, or
  say what was done.

### Web UI
- The arrow stays on screen, showing the last state, after "Stop." or when a target becomes
  unsafe. Send a `{"type": "state", "idle": true}` and hide the arrow.
- Push-to-talk:
  - Handle `pointercancel`, which Android fires on a scroll gesture and which leaves recording
    on.
  - Set `touch-action: none` on `#talk`.
  - `getUserMedia` per press adds latency and clips the first syllable (**V4**). Open the
    stream once and keep it.
  - A rejected `start()` (permission denied) leaves the button stuck in "listening".

- No service worker, so it isn't installable as a PWA on Chrome (**V1**).
- Night mode: gallery images and the live stack are full-brightness color. Add a red/dim filter
  (`filter: grayscale(1) sepia(1) hue-rotate(-50deg)` or similar) when not in day mode
  (**H2**).
- The "Day mode" button label never toggles.
- `get_location` is broadcast to every tablet, so every tablet answers with its own GPS fix.
  Send it only to the requester.
- `server.py:228-229`: `data.get("alt")` isn't cast to float. A string would break the
  `:.0f` format in `site_store.save`.
- `server.py:208-210`: every new connection re-broadcasts `get_location` to all clients until a
  site is saved.

### Firmware
- `astro_mcu.ino:87`: the `parseInt` comment says "false on … trailing junk", but it doesn't
  check trailing junk; the callers do.
- DS18B20 returns 85.0 °C as its power-on value before the first conversion. Treat 85.0 on the
  first read as invalid. Otherwise the heaters under-heat at startup.
- `mcu_protocol.py:13` says "heaters off after 10 s without [a PING]", but the firmware also
  treats `HEAT` as a heartbeat (`.ino:104`). Document that.
- Both heater channels always get the same percentage (`mcu.py:70-71`). That's fine for now;
  note it, because the finder lens and the secondary dew differently.
